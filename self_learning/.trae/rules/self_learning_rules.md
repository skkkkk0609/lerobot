## 三、文件命名规范

### 3.1 脚本文件（.py）

两种命名模式，根据场景选用：

#### 模式 A：分阶段实战（硬软件结合，推荐）

```
phase{序号}_{动词}_{对象}.py
```

| 部分 | 说明 | 示例 |
|------|------|------|
| 序号 | phase1 / phase2 / phase3 | `phase1` |
| 动词 | 描述做什么 | `sim2model`、`move_robot`、`deploy` |
| 对象 | 操作的对象 | `robot`、`data` |

示例：
```
phase1_sim2model.py       ← 好 ✅ 阶段 1：模拟→模型
phase2_move_robot.py      ← 好 ✅ 阶段 2：真机通信
phase5_deploy.py          ← 好 ✅ 阶段 5：最终部署
```

#### 模式 B：顺序步骤（纯软件学习）

```
step{序号}_{动词}_{对象}.py
```

示例：
```
step1_load_model.py       ← 好 ✅
step2_explore_data.py     ← 好 ✅
```

```
model_loader.py           ← 差 ❌（没有序号，看不出顺序）
run.py                    ← 差 ❌（太笼统）
```

### 3.2 文档文件（.md）

```
{GUIDE或TUTORIAL或README}_{主题}.md
```

示例：
```
VLA_GUIDE.md              ← 好 ✅（入门指南）
README.md                 ← 好 ✅（文件夹说明）
```

### 3.3 数据集 / 配置 / 权重文件

放在对应主题文件夹下的子目录中：
```
<主题>/
├── data/                 ← 小型数据集或索引文件
├── checkpoints/          ← 模型检查点
└── configs/              ← 自定义配置文件
```

## 四、Agent 行为规则

### 4.1 新建内容前

1. **必须先读取本规则文件**（`self_learning\.trae\rules\self_learning_rules.md`）
2. 检查是否已有相同主题的文件夹，有则在原文件夹**追加**，无则新建
3. 新建文件夹前询问用户确认主题名

### 4.2 新建文件夹

```bash
# 模板
mkdir d:\lerobot\self_learning\<主题英文名> -Force
```

创建后必须在文件夹内放置：
- **至少一个** `README.md`：说明该主题的学习目标和文件清单
- 或直接放入脚本文件（脚本名足够自解释时可省略 README）

### 4.3 创建脚本

- 脚本必须包含文件头注释，说明**作用、输入、输出**
- 脚本按学习顺序编号（step1 → step2 → step3 ...）
- 每个脚本不超过 **80 行**（保持简洁，方便新手阅读）
- 禁止在 self_learning 下创建 `__init__.py`（这不是 Python 包，是学习脚本集合）

### 4.4 移动 / 删除

- **禁止随意删除**已存在的文件夹或文件
- 如需重组，先用 `Grep` 检查是否有交叉引用
- 重组后更新本规则文件中的"已存在的主题文件夹"表格

### 4.5 脚本命名语言

- 文件名：英文（方便命令行操作）
- 注释：中文（用户是中文用户）
- 打印输出：中文（用户是中文用户）

## 五、主题分类建议

当 Agent 需要为用户创建新内容时，按以下分类决定放哪个文件夹：

| 用户问题类型 | 对应文件夹 | 示例 |
|-------------|-----------|------|
| VLA 入门/概念 | `vla_basics` | 加载模型、理解数据格式 |
| SmolVLA 深入 | `smolvla_deep_dive` | 源码解读、架构分析 |
| Pi0 系列 | `pi0_learning` | Pi0 加载、Pi0Fast 对比 |
| 数据集操作 | `dataset_skills` | 录制、转换、可视化 |
| 训练相关 | `training_practice` | fine-tune、超参调优 |
| 部署相关 | `deployment` | WebSocket 集成、真机推理 |
| 临时实验 | `notes` | 临时测试、草稿代码 |
